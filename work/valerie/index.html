Pass 1 · Overview

Who is Valerie?

Valerie lives inside CognitiveOS, a personal operating layer for my day on iPhone and Mac. She talks, listens, remembers, learns a task by watching it once, and operates the Mac when asked.

Why it matters. An assistant that can press buttons on a real computer needs more than a capable model: whatever decides what it may do has to be something it can’t talk its way past. So the rule that shapes the system is that the model decides intent, and code keeps control. In her own design notes: Ram decides. Valerie interprets, argues, remembers and proposes. The System owns the truth.

  • Built: a native SwiftUI app with a turn pipeline, long-term memory with trust set in code, skills learned by demonstration, and a living pixel-art presence. About 107,000 lines of Swift, in five weeks.
  • Runs here: the same boundary, for this website only. Send it a move below and watch which check stops it. In her dock you can wake a small model fine-tuned for this site, in your own browser: it proposes a move, the same checks judge it, and it runs only when you press it.
  • Limits: the source is private, the native interface was not driven for this site, and memory recall is measured on a public benchmark (retrieval only), not on my own questions.

Pass 1 · Overview

What did Ram build, and what changed?

My contribution

What I built
CognitiveOS for iPhone and Mac, with Valerie inside it: the one-turn pipeline (fast path, one typed move, validation, an existing engine), a deterministic risk policy over 56 declared desktop capabilities, long-term memory with a verbatim ledger and trust tiers, skills learned by demonstration, and her presence. Then the same boundary, adapted, for this site’s guide, with a guard in front of its validator.
The tradeoff I chose
Authority stays with deterministic code. A model may propose one typed move per turn over ids the turn issued. macOS permissions, the app’s settings and a fixed risk policy decide whether it runs, and the model controls none of them. The cost is flexibility: anything outside the closed list of 26 moves simply can’t happen, and risky actions always wait for a yes.
What changed
Every action became checkable: validated against what existed that turn, refused or confirmed by fixed rules, and recorded as a receipt. Outside text, from a screen, a paste or PHAROS, can be discussed but can never act or become a fact. Memory retrieval reports R@5 0.908 on LongMemEval’s 500 questionsreported · retrieval only.

Pass 2 · How it works

What’s the idea, in one picture?

Think of a stage manager and a brilliant actor. The actor can suggest anything, but only cues written into tonight’s script can happen, and the stage manager checks each one against the stage as it is right now.

  1. 01Hear it

    A held key, her name or a typed line starts a turn. Stop, a click or an exact skill name runs at once, with no model.

  2. 02Propose one move

    The turn issues ids for what exists right now, and one model call returns her words and one move over those ids.

  3. 03Check it in code

    A validator, macOS permissions, her settings and a fixed risk policy each have a veto. The model has none.

  4. 04Do it

    An existing engine does the work: the desktop, a skill, the System, or a PHAROS lookup.

  5. 05Remember it

    Every event is kept verbatim, with a trust tier set in code. Outside text can never become a fact.

  6. 06Be someone

    A day of her own, lines from a rule book, a live body and a local voice. Never a stand-in for a result.

What happens in one turn on the Mac?

One model call per turn. Everything around it is deterministic.

Try this · Trace the four steps. This page describes the native turn; no model call runs here.

  1. A fast path answers stop, a click, an exact skill name and a short list of commands, with no model.
  2. Anything else gets one model call, which can only return a typed move over ids issued for that turn.
  3. Code on the Mac validates that move. A question never runs anything.
  4. An existing engine carries it out.
