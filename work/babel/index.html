Overview

The problem BABEL sets out to solve. 1 minute

Pass 1 · Overview

What problem does BABEL solve?

A novel and a visual scenario carry the same story with very different structure.

BABEL is a Python/React prototype that transforms prose into structured visual-scenario blocks, with character customization, chapter navigation, glossary tooling and a co-appearance graph.

My contribution

What I built
A Python pipeline that turns prose chapters into typed scene blocks (narration, dialogue, thought and action, each with its speaker), and a React reader that renders those blocks, keeps characters consistent through a glossary, and draws which characters share chapters.
The tradeoff I chose
The story is turned into typed blocks rather than into finished pictures or video. Typed blocks can be checked against the sentence they came from, and the character graph only counts shared chapters instead of guessing at relationships.
Where it stands
The source was reviewed at commit 3970010, but the full application was not run. The review found gaps in how the stages are wired together, so the example on this page is an original story written by hand in BABEL’s format, not a live result.

How it works

The decisions behind BABEL, and then a short story set out in its intended structure. 3 minutes

Pass 2 · How it works

How was it built, and why that way?

  1. Type the story. Typed blocks give the reader something more precise to render than a wall of text.
  2. Keep characters consistent. Glossary extraction, YAML storage and prompt context carry names and details between chapters.
  3. Count, do not infer. The character graph counts shared chapters. It makes no claim about relationships.
BABEL architectureSourceBlocksContextReaderOpen diagram

The intended path through the prototype, drawn from source review. It is not a claim that every stage is connected end to end.

  1. 01Source

    Prose chapters enter with a source hash, so an output can be tied to its input.

  2. 02Blocks

    Text becomes typed story blocks: narration, dialogue, thought and action, with speaker and tone.

  3. 03Context

    A glossary provides character context. It is glossary context, not verified vector retrieval.

  4. 04Reader

    A React reader renders typed blocks, with character customization and chapter navigation.

A source audit identified orchestration and reliability gaps. The portfolio demo uses original text and a bounded fixture while those integrations are hardened.

Deep dive

What the source code shows, what BABEL cannot do yet, and what comes next. 2 minutes

Pass 3 · Deep dive

What does the source show?

  • BABEL is a Python/React visual-scenario reading and prose-transformation prototype with typed blocks, character customization and chapter navigation.

    ● Source verifiedLedger

    Source reviewed at commit 3970010; the full app and live transformation were not executed.

  • BABEL includes glossary extraction, YAML storage and prompt context injection.

    ● Source verifiedLedger

    No verified embedding-based RAG. Default batch glossary wiring and graph schema interoperability have gaps.

  • BABEL implements a character co-appearance graph from chapter speakers and a circular SVG viewer.

    ● Source verifiedLedger

    Edges count shared chapters, not inferred social relationships. A glossary schema mismatch was reproduced.

Pass 3 · Deep dive

What are its limits?

  • A source audit identified orchestration and reliability gaps. Those integrations need hardening before any live service.
  • The full application and live transformation were not executed during review.
  • This is structured text. BABEL does not generate video.
  • Only original text appears on this site.

Pass 3 · Deep dive

What would Ram test next?

Harden the integration boundaries, then test how faithfully every beat and speaker survives the transformation. A source hash proves which input was used; it does not prove the adaptation is faithful.
