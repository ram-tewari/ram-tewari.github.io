Source verification

Code is read at the indexed commit and compared with its Git blob SHA before it is returned.

▣ Recorded run

PHAROS at 975a38dMIT license

How it works

PHAROS stores pointers instead of source. To answer, it fetches the file at the pinned commit, hashes the whole file the way Git does and compares that with the SHA recorded at index time.

A mismatch withholds the code and reports why. Cached bytes pass through the same comparison.

Recorded runs through it

  1. A question reaches verified sourceOne question, asked the way an assistant asks it: a real MCP call, a real dense search, and five files fetched from GitHub and checked against their Git blobs.
  2. What the blob check does with a mismatchThe same pointer through the same call, three times. Only the expected SHA changes.

Source evidence

  • The Git blob hashbackend/app/codeintel/source.py:85–86Git's own object hash: SHA-1 over a header and the file's bytes. A span of a file cannot be checked, so the whole file is hashed.
  • Compare before returningbackend/app/codeintel/source.py:141–162The check itself. A mismatch returns unavailable:content_mismatch and no code. With no recorded SHA, code is returned with verified left false.
  • Load at the pinned commitbackend/app/codeintel/source.py:121–138Cached bytes come back through the same comparison, because the check happens after this returns.
  • Fetch from an allowlisted hostbackend/app/codeintel/source.py:97–118Https only, allowlisted hosts, no redirects, a size cap and a timeout.
  • Resolve pointers concurrentlybackend/app/codeintel/source.py:165–173Eight workers at most. It never raises, so one unavailable file cannot fail the response.
  • Pointer to requestbackend/app/codeintel/context.py:116–151The blob SHA comes from the row written at index time, not from the file being checked.

Limits

  • This proves the bytes match the indexed commit. It says nothing about whether the code is correct or secure.
  • With no SHA on record, source is still returned, marked unverified. Files PHAROS indexes get a SHA; the check depends on that row.
